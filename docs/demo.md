# 三分钟演示脚本（离线 mock）

> 只演示候选目录内的合成数据和**离线模拟**。页面/CLI 不提供 real、真实数据库
> 或独立命名查询；表、SQL、查询计数均为 mock 占位，不是真实查询结果。
> 开始前启动 Streamlit，不设置任何 API key。

## 0:00–0:30 范围

- 合成 MES 数据；模型只能产生 `query / clarify / refuse`，查询只走三个命名查询的
  演示参数。
- 不是通用 Text2SQL；不写业务收益/准确率；页面/CLI 不启停数据库。

## 0:30–1:20 正常查询 + 采纳依据

输入：

```text
列出各产线当前累计实际产量快照（不按日期）。
```

预期：`ok / line_snapshot`，返回 L01/L02/L03 三行，L03=0；页面显示
“演示口径已确认”“合成数据”和最终 plan/params。表是固定 mock 样例。

依据：演示看采纳计划、参数、口径和 trace；显示的 SQL 是
`SELECT /* offline mock */ 1;` 和 `queries=2`，都是模拟占位，不是真实 SQL/计数。
历史真实 SQL 与模型调用只作为归档摘要，不在本候选重放，也不由本 mock 证明。

## 1:20–1:50 澄清

输入：

```text
我想看工单完成情况。
```

预期：`needs_clarification`，提示补充 `line_id`；`queries=0`，无 SQL。
输入 `line_id=2` 也会澄清：公开 mock 只覆盖 `line_id=1`，不会返回 L01 的表。

## 1:50–2:20 拒绝

输入：

```text
请删除工单表的数据。
```

预期：`refused`，写操作/目录外不执行；`queries=0`，无 SQL。

## 2:20–3:00 边界与历史摘要

- 三个查询：line_snapshot、work_order_progress、downtime_details；
  公开 mock 的工单仅 line_id=1，停机仅固定
  `2026-11-01T00:00:00+08:00..2026-11-02T00:00:00+08:00`；其他参数澄清。
- 缺窗口/反向窗口/未知别名澄清；NULL/空表不画成 0。
- 单问 30s、模型 2 次、SQL 2 条、纠错 1 次；候选只有 mock。
- 历史合成实测摘要（归档，不是本候选重跑）：12 题 × full/focused，24 请求/
  25 transport，input 28501/output 1082；12/12 是 pilot 工程匹配，不是 30 题
  企业准确率，其余 18 题未跑。详见 C 的公开摘要。
